# FolioMend

FolioMend 是一款本地运行的扫描 PDF 整理工具，用于批量统一页面的可见宽度、处理裁剪框，并在尽量保留文字层、矢量内容和书签的前提下减小扫描文档体积。

## 功能

- 批量选择或拖放 PDF 文件。
- 以 `CropBox` 可见区域为基准统一页面宽度。
- 目标宽度可选择自动识别或自定义（手动输入，单位 pt）。
- 可选将 `MediaBox` 真正裁剪到可见区域。
- 识别彩色、灰度和纯黑白图像，采用不同策略压缩；支持 JPEG、JPEG 2000（JPX）、Flate、LZW、RunLength 图像流及 ASCII85／ASCIIHex 多层过滤链；CCITT／JBIG2 黑白编码直接保留。
- 自动使用硬件 GPU 加速灰度转换、黑白位打包和大图缩小；不可用或运行失败时回退到 CPU。
- 同步调整书签等目标坐标，避免页面缩放后定位错乱。
- 输出文件自动添加 `_normalized` 后缀，并避免覆盖已有文件。
- 处理进度精确到当前文件、页面和图像。
- 按页面与尺寸、图像优化、文档修复、书签与导航分类设置处理选项。
- 桌面采用文件工作区与处理设置双栏布局，顶部和操作栏始终可见，长列表仅在面板内滚动。
- 文件列表与处理结果在同一工作区切换；处理完成后自动显示结果，单个文件详情默认折叠，也可全部展开或收起。

FolioMend 不会上传 PDF；文件选择、解析和输出均在本机完成。

## 下载与使用

在本仓库的 GitHub Releases 页面下载 Windows x64 Portable ZIP，解压后运行 `FolioMend.exe`，无需安装 FolioMend。

运行要求：Windows 10/11 x64，已安装 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。Portable 包不包含该运行时；WebView 缓存仍保存在系统用户目录。

选择或拖入 PDF 后开始处理，输出文件保存在原文件目录，请确保目录可写。

默认窗口为 1180 × 780，最小窗口为 640 × 600，启动时居中并限制在屏幕可用工作区内。窄窗口自动改为上下两个面板；调整窗口大小时，文件、设置和结果仍在各自区域内滚动，操作栏保持可见。

设置区默认使用紧凑视图，点击“显示说明”可展开选项解释。目标宽度、页面裁剪及修复选项旁的 ⓘ 支持悬停、点击和键盘聚焦查看说明；按 Esc 或点击外部关闭浮层，界面布局保持不变。书签清理前会确认的提示始终可见。切换自动识别与自定义宽度时，输入框保留原位置。

处理完成后，工作区自动切换至“处理结果”。结果容器顶部固定显示文件总数及成功、失败数量，下方列表独立滚动。点击单个文件可查看完整处理详情；“全部展开”和“全部收起”仅控制文件详情，文件列表和统计栏保持可见。也可切回“文件列表”。处理中暂时禁用添加、移除和清空，避免批次列表发生变化。

开启“统一页面宽度”后，可选择目标宽度模式：

- **自动识别（默认）**：为每个 PDF 分别计算目标可见页宽；通常取最大宽度，当最大宽度超过 P95 的 1.2 倍时取 P95。
- **自定义**：输入大于 0 的目标宽度，本批次所有 PDF 都按该值等比缩放。单位为 pt（72 pt = 1 英寸，A4 短边约 595.28 pt）。

应用会记住宽度模式和输入值。关闭统一页面宽度后，这些宽度设置不参与处理。

## 高级图像设置

点击“图像优化”中的“高级设置”，在独立对话框调整图像压缩。主页只显示当前 JPEG 质量、图像长边和颜色转换摘要。点击“应用设置”后记住参数；取消或按 Esc 放弃本次修改；恢复默认仅调整对话框中的草稿。

- **自动保护封面与图片**：默认开启。10 页及以上文档将前 3 页和后 2 页实际绘制的图像作为疑似封面；短文档仅考虑首页和末页。其余图像在减色和缩小前，通过最长边至多 768 个采样点的网格分析局部灰阶／通道分布；连续色调区域达到约 3% 时作为疑似照片或渐变插图。触发后保留颜色与灰阶，不执行转灰度、减色或新二值化；JPEG 质量取用户值与 90 的较大值，启用降采样时长边上限取用户值与 3000 px 的较大值。关闭 JPEG、关闭降采样及更保守的设置仍有效，且不会放大原图。新候选仍须节省超过 2% 才替换，否则保留原流。共享图像只处理一次，若出现在首尾页则统一保护。识别属于启发式，可能误判正文，也可能漏掉小照片、半色调图或普通线条插图；结果会列出判断依据、候选参数和是否保留原图。关闭开关可恢复所有图像统一使用手动设置。

- **JPEG 压缩**：质量范围 1–100，默认 80，同时适用于彩色、灰度和黑白图像。编码时按当前图像的实际符号频率生成 Huffman 码表，减少编码开销；码表优化本身不增加画质损失，但会增加编码时间和内存占用。彩色图像保持 4:4:4 色度采样。质量越低通常体积越小。关闭后使用无损 Flate 编码；降采样和减色仍可能改变像素。
- **降低分辨率**：默认将长边限制为 2000 px，范围 256–20000 px，保持比例且不放大；彩色、灰度和黑白共用此设置。关闭后保留图像像素尺寸。
- **允许彩色转为灰度／黑白**：默认关闭。开启后，采样像素的 RGB 最大差值超过“颜色差异阈值”时计为彩色；彩色像素比例不超过上限才转换。默认差异为 20、比例上限为 5%；两个值越高越容易转换，上限 100% 允许全部可处理的彩色图像转为灰度。
- **黑白／灰度减色**：默认保留原始灰阶，可逐档选择 128、64、32、16、8、4 级灰阶。这些档位不会自动将接近黑白的 8-bit 图像二值化；原本的 1-bit 黑白图仍保持黑白。纯黑白作为独立分组选项，按灰度阈值 160 二值化，适合黑字白底，会丢失照片、阴影和浅色笔迹的灰阶。
- **彩色减色**：默认保留原始颜色，可选择每个 RGB 通道 64、32、16、8、4、2 级，最多分别为 262,144、32,768、4,096、512、64、8 种颜色。这里的级数是每通道色阶，不是整张图的调色板大小；低档位可能出现色带和颜色失真。
- **自适应减色**：灰度和彩色均可选择“自动（自适应）”。在转换、缩小之后，使用完整像素直方图评估候选档位；灰度选择 4–128 级，彩色选择每通道 2–64 级，平均通道绝对误差不超过 2/255，最大逐色通道误差不超过 8/255。禁止把 3–252 范围的值直接量化到黑白端点，减少浅色笔迹被背景吞掉；连续色阶较多时，灰度至少保留 64 级、彩色每通道至少保留 32 级。没有合适候选则保留层次。自动模式不会把 8-bit 图像二值化，且仍遵守彩色转灰度开关；JPEG 自身的误差不包含在这些减色约束中。逐图处理明细显示实际选择和原因。默认仍保留原始层次。
- **旧设置兼容**：旧版“适度减色”映射为 32 级，灰度不再自动二值化；旧版“强力减色”在灰度中映射为纯黑白，在彩色中映射为每通道 8 级。主页摘要及结果详情显示具体档位。

减色在编码前执行，JPEG 编码可能产生近似颜色。彩色转换先于减色：转换成功的图像使用黑白／灰度档位，未转换的图像使用彩色档位。“保留层次”不关闭 JPEG 压缩或降采样。纯黑白图像会在 JPEG 和 1-bit Flate 之间选择更小的结果。新图像必须比原图像流小超过 2% 才替换；带透明蒙版、自定义 Decode 像素映射及不支持的解码参数或编码会保留。图像设置不改变 PDF 的文字层、矢量内容和书签。JPX 支持 JP2 容器和原始 JPEG 2000 码流中的灰度／RGB 图像，复用缩小、减色与 JPEG／Flate 重编码流程；带内嵌透明度、ICC／CMYK／索引颜色及尺寸不匹配的 JPX 图像保留原样。

Flate／LZW 支持 PNG（10–15）和 TIFF（2）预测器；灰度／RGB 原始像素支持 1、2、4、8、16 bit（16 bit 转为 8 bit 后重编码）。支持按顺序组合 ASCII85、ASCIIHex、RunLength、Flate、LZW，并在末层解码 JPEG／JPX；每层 DecodeParms 独立解析。已经使用 CCITT／JBIG2 的纯黑白图像直接跳过，在结果中单独标为“已是黑白编码”。解码限制中间缓冲区大小，异常输入保留原流。解码库随应用编译，无需另装系统解码器。

## 处理结果统计

批次统计显示文件数量、成功／失败数和合计体积变化。没有输出的文件按原始体积计入，避免把“无需处理”误算为节省 100%。每份文件展开后，可查看图像优化的实际结果：

- 实际写回／扫描图像对象数、保留原图张数、图像流的前后体积和节省比例、总像素前后变化。
- 实际彩色转灰度／黑白、二值化、色阶量化、降采样，以及 JPEG / Flate 编码的张数；同一图像可以参与多项处理。
- 颜色处理图像的平均采样颜色数前后对比。每张最多均匀采样 50,000 个像素，比较输入与编码前结果，数值包含缩小、转换和量化的影响；不代表整个 PDF 的精确颜色总数，JPEG 编码后可能出现近似颜色。
- 保留原因：收益未超过 2%、已是黑白编码、蒙版或特殊解码参数、编码／尺寸不支持、重新编码失败，以及整份文件未变小而放弃候选输出。
- 可展开的逐图明细：图像对象编号、实际处理、输入／输出位深、像素尺寸、采样颜色数和图像体积变化；另可查看本次使用的设置快照。

按唯一图像对象计数，共享资源只计一次。已尝试但未采用的候选不计入颜色处理和降采样成果；若最终没有保留输出，图像统计回退到原图。GPU / CPU 张数仍用于显示预处理工作量，包含未采用的候选。

## GPU 加速

“图像优化”区提供“GPU 加速”开关，默认开启并记住选择。关闭后，图像预处理全部使用 CPU；关闭图片压缩时该开关暂时禁用，保留选择。启用“压缩扫描图像”和“GPU 加速”后，程序通过 `wgpu` 自动检测硬件显卡，Windows 使用 DirectX 12 或 Vulkan，macOS 使用 Metal。无需安装 CUDA。小于 512 × 512 像素总量的图像使用 CPU，以避免 GPU 上传和回读开销。

GPU 负责灰度转换、纯黑白位打包和灰度图的三角滤波缩小；图像识别、JPEG 解码及 JPEG / Flate 编码仍在 CPU 上执行。是否提速取决于扫描图大小、显卡和编码耗时。缩小算法保持原有三角滤波，GPU 浮点运算可能产生最多约一个灰度级的舍入差异。

没有兼容显卡、驱动初始化失败、单张图像超过缓冲区限制时自动使用 CPU。设备丢失、计算失败或超过 10 秒未回读时，本次进程后续图像也使用 CPU。CPU 保留原有并行处理。结果详情显示 GPU 型号、回退原因及 GPU / CPU 预处理张数（包含未达到体积节省阈值而保留原图的图像）。彩色图像的缩小和减色目前使用 CPU；转为灰度后可使用 GPU。带透明遮罩的图像保留原样。

硬件验证可运行：

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml hardware_ -- --ignored --nocapture
```

## 开发环境

- [Node.js](https://nodejs.org/) 22.12 或更高版本
- [Rust](https://www.rust-lang.org/tools/install) 1.92 或更高版本
- [Tauri 2 系统依赖](https://v2.tauri.app/start/prerequisites/)

## 本地运行

```powershell
npm install
npm run dev
```

也可以使用 PowerShell 构建脚本：

脚本兼容 Windows PowerShell 5.1 和 PowerShell 7。编辑 `build.ps1` 时请保留 **UTF-8 with BOM** 编码，否则 Windows PowerShell 5.1 可能将中文误读为本地编码，导致乱码及“字符串缺少终止符”等解析错误。

```powershell
.\build.ps1 -Dev
```

## 测试

```powershell
npm run check
npm run frontend:build
cargo test --manifest-path src-tauri/Cargo.toml
```

前端使用 ES Module 和 Vite 构建，Tauri 开发及发布命令会自动启动或构建前端。直接运行 Rust 测试前需先生成 `dist/`。

## 构建安装包

```powershell
npm run build
```

或：

```powershell
.\build.ps1 -Release
```

构建产物位于 `src-tauri/target/release/bundle/`。
